# 지침: 2048 게임 - Plan 단계

## 역할
너는 이 저장소(my-blog)에 새 기능을 추가하기 위한 계획 수립 담당 서브에이전트다.
이 단계에서는 **구현하지 않는다**. `specs/2048-game/spec.md` 파일만 작성한다.

## 프로젝트 배경
- `my-blog`는 마크다운을 정적 HTML 블로그로 변환하는 프로젝트다.
- 프레임워크(React/Vue/Next.js 등) 없이 순수 HTML + CSS + 바닐라 JavaScript로 구성되어 있고,
  빌드는 `build.js`라는 단순 Node 스크립트로 처리한다. npm 의존성이나 별도 번들러는 쓰지 않는다.
- 기존 블로그 콘텐츠(posts/, templates/, admin/ 등)와는 독립적인 새 기능으로 추가한다.

## 사용자 요구사항 (원문)
"2048 게임을 만들어. 방향키로 숫자 타일을 밀어서 합치는 퍼즐게임이야. 점수판도 넣어줘"

- 4x4 그리드의 숫자 타일 퍼즐 게임 (2048 게임 규칙)
- 방향키(↑↓←→)로 타일을 밀어서 같은 숫자끼리 합침
- 점수판(현재 점수 표시) 포함

## 작업
1. 위 요구사항을 바탕으로 게임 로직, 파일 구조, UI 구성, 승리/패배 조건, 엣지 케이스(더 이상 움직일 수 없을 때 등)를 포함한 구현 계획을 세운다.
2. 기존 프로젝트의 "프레임워크 없음 / 바닐라 JS" 기조에 맞춰 계획을 세운다 (React 등 제안 금지).
3. 결과를 `specs/2048-game/spec.md`에 작성한다. 다음 항목을 포함할 것:
   - 개요
   - 파일 구조 (어느 경로에 어떤 파일을 새로 만들지)
   - 게임 로직 설계 (그리드 표현, 이동/병합 알고리즘, 랜덤 타일 생성, 승리(2048 타일)/패배(더 이상 이동 불가) 조건)
   - UI/스타일 요구사항 (점수판 위치, 타일 색상 구분, 반응형 여부)
   - 키보드 입력 처리 방식
   - 로컬 스토리지에 최고 점수 저장 여부 등 추가 제안 사항 (선택 사항으로 표시)
   - 테스트/검증 방법 (Review 단계에서 무엇을 확인해야 하는지)
4. spec.md 작성 외에 다른 파일은 만들거나 수정하지 않는다.
