# 2048 게임 - 구현 계획 (spec.md)

## 개요
- 방향키로 숫자 타일을 밀어 같은 숫자끼리 합치는 4x4 2048 퍼즐 게임을 추가한다.
- 기존 블로그 콘텐츠(posts/, templates/, admin/, build.js 파이프라인)와는 완전히 독립된 정적 페이지로 구현한다.
- 프레임워크 없이 순수 HTML + CSS + 바닐라 JS로 작성하며, 별도 빌드 과정 없이 index.html을 그대로 열어 실행 가능해야 한다.
- `admin/` 폴더가 이미 "빌드 파이프라인과 무관한 독립 기능" 선례이므로 동일한 패턴(자체 폴더 + 자체 index.html/css/js)을 따른다.

## 파일 구조
프로젝트 루트에 새 폴더를 만든다 (기존 `admin/` 폴더와 동일한 위치 수준).

```
2048-game/
  index.html   # 게임 페이지 마크업 (보드, 점수판, 새 게임 버튼, 오버레이)
  style.css    # 게임 전용 스타일 (그리드, 타일 색상, 반응형)
  game.js      # 게임 로직 (상태 관리, 이동/병합, 키보드 입력)
```

주의사항 (구현 시 반드시 지킬 것):
- `build.js`는 `docs/`를 매번 삭제 후 재생성하고 `assets/css`, `assets/js`, `assets/images`만 복사한다. 따라서 게임 파일을 `docs/` 하위나 `assets/js/` 등 공용 폴더에 두지 않는다. 새 `2048-game/` 폴더는 빌드 스크립트가 건드리지 않는 영역에 둔다.
- `build.js`, `templates/*`, `posts/*`, `admin/*` 등 기존 파일은 수정하지 않는다.
- (선택) 메인 블로그에서 게임으로 가는 링크를 추가하고 싶다면 `templates/layout.html`의 헤더에 `<a href="/2048-game/">2048</a>` 한 줄을 추가하는 정도로 최소화하고, 이는 별도 승인 후 진행한다.

## 게임 로직 설계 (game.js)

### 상태
- `board`: 4x4 2차원 배열, `0`은 빈 칸.
- `score`: 현재 점수 (숫자).
- `bestScore`: 최고 점수 (선택 사항, localStorage 연동).
- `isGameOver`, `hasWon`: 상태 플래그. `hasWon`은 승리 메시지를 1회만 띄우기 위한 플래그이며, 승리 후에도 "계속하기"로 플레이를 이어갈 수 있게 한다.

### 초기화
- 4x4 빈 보드 생성 → `addRandomTile()` 2회 호출 → 렌더링.

### 랜덤 타일 생성 (addRandomTile)
- 빈 칸 좌표 목록을 구한 뒤 무작위로 하나 선택.
- 90% 확률로 값 `2`, 10% 확률로 값 `4`를 배치.
- 빈 칸이 없으면 아무 것도 하지 않음(호출 전에 항상 빈 칸 존재를 보장).

### 이동/병합 알고리즘
네 방향을 각각 구현하지 않고, "왼쪽으로 밀기" 로직 하나를 만들고 회전/반전으로 재사용한다.

1. `slideRowLeft(row)`:
   - `0`을 제거해 값들을 왼쪽으로 압축.
   - 왼쪽부터 순회하며 인접한 두 값이 같으면 병합(합산 값으로 교체, 뒤 칸은 제거) — **한 턴에 하나의 타일은 한 번만 병합**되도록 병합된 인덱스는 다시 검사하지 않는다. (예: `[2,2,2,0]` → `[4,2,0,0]`이 되어야 하며 `[4,4,0,0]`이 되면 안 됨)
   - 병합으로 생긴 값을 `score`에 누적.
   - 다시 길이 4가 되도록 뒤쪽을 `0`으로 채움.
2. `moveLeft(board)`: 각 행에 `slideRowLeft` 적용.
3. `moveRight(board)`: 각 행을 반전 → `slideRowLeft` → 다시 반전.
4. `moveUp(board)` / `moveDown(board)`: 보드를 전치(transpose)한 뒤 `moveLeft`/`moveRight` 적용 후 다시 전치.
5. 이동 전후 보드를 비교해 **변화가 있었는지(changed) 판정** → 변화가 있을 때만 `addRandomTile()` 호출 및 리렌더링. 변화가 없으면(막힌 방향으로 이동 시도) 아무 것도 하지 않는다 — 이는 반드시 지켜야 할 엣지 케이스다.

### 승리 조건
- 이동/병합 결과 보드에 `2048` 이상 값이 등장하면 `hasWon = true`로 설정하고 승리 오버레이 표시. "계속하기" 버튼으로 플레이 지속 가능(선택 사항).

### 패배 조건 (더 이상 이동 불가)
- `canMove(board)` 함수:
  - 빈 칸이 하나라도 있으면 `true`.
  - 빈 칸이 없으면 모든 셀에 대해 오른쪽/아래 인접 셀과 값을 비교, 같은 값이 하나라도 있으면 `true`.
  - 위 두 조건 모두 거짓이면 `false` → 게임 오버 오버레이 표시.
- 매 이동 시도 후(보드에 변화가 있어 새 타일이 추가된 다음) `canMove()`를 호출해 게임 오버 여부를 판정한다.

### 재시작
- 보드/점수/플래그 초기화 후 새 타일 2개 생성, 오버레이 숨김.

## UI/스타일 요구사항 (index.html, style.css)
- 페이지 전체를 화면 중앙에 배치. 점수판은 보드 상단에 위치하며 "SCORE"(현재 점수)와 "BEST"(최고 점수) 두 박스를 나란히 표시.
- 보드는 CSS Grid 4x4, 타일 사이 gap을 두고 보드 자체는 둥근 모서리의 배경 박스로 표현.
- 타일 색상은 2048 원작 팔레트를 따른다: 값별로 `tile-2`, `tile-4`, `tile-8` … `tile-2048` 클래스로 배경색을 구분하고, `2048`을 초과하는 값은 공통 어두운 팔레트(`tile-super`)로 처리. 숫자 자릿수가 늘어날수록(3~4자리) 폰트 크기를 줄여 타일 안에 맞춘다.
- 반응형: 보드 너비를 `min(90vw, 420px)` 등으로 지정하고 `aspect-ratio: 1 / 1`로 정사각형을 유지해 모바일에서도 잘리지 않게 한다. 폰트 크기는 `clamp()`로 화면 크기에 대응.
- 게임 오버/승리 시 보드 위에 반투명 오버레이 + 메시지 + "새 게임" 버튼 표시.
- 타일 등장/병합 시 간단한 CSS transition(scale, opacity)으로 애니메이션 효과를 주는 것을 권장하되 필수는 아니다.
- 기존 블로그의 다크모드 변수(`--color-bg`, `--color-text` 등)와 어울리는 자체 색상을 `style.css`에 정의할 수 있으나, 독립 페이지이므로 `assets/css/style.css`에 대한 의존은 만들지 않는다(선택적으로 유사한 팔레트만 참고).

## 키보드 입력 처리 방식
- `document`에 `keydown` 이벤트 리스너를 등록.
- `ArrowUp` / `ArrowDown` / `ArrowLeft` / `ArrowRight` 키를 확인해 각각 대응하는 이동 함수를 호출.
- 방향키 입력 시 `event.preventDefault()`를 호출해 페이지 스크롤을 막는다.
- 게임 오버 상태에서는 키 입력을 무시한다.
- (선택) 애니메이션 처리 중 중복 입력을 막기 위한 간단한 잠금 플래그를 둘 수 있다.

## 추가 제안 사항 (선택)
- localStorage에 `best-score` 키로 최고 점수를 저장하고, 페이지 로드 시 불러와 표시.
- 모바일 대응을 위한 터치 스와이프 지원(`touchstart`/`touchend` 좌표 비교로 방향 판정).
- 1단계 실행 취소(undo) 기능.
- 타일 이동/등장/병합에 대한 CSS 애니메이션.
- 블로그 헤더 네비게이션에 게임 페이지로 가는 링크 추가(별도 승인 필요).

## 테스트/검증 방법 (Review 단계 체크리스트)
- 상/하/좌/우 각 방향키 입력 시 타일이 올바른 방향으로 이동·병합되는지 확인.
- `[2,2,2,0]` 형태처럼 같은 값이 3개 연속일 때 한 턴에 한 번만 병합되는지 확인(`[4,2,0,0]`이 되어야 함).
- 실제로 보드에 변화가 생긴 이동에서만 새 타일이 생성되는지, 변화 없는(막힌 방향) 이동 시에는 새 타일이 생기지 않는지 확인.
- 병합될 때마다 점수판에 병합된 값만큼 정확히 누적되는지 확인.
- 타일 값이 2048에 도달하면 승리 메시지가 표시되는지 확인.
- 보드가 가득 차고 더 이상 병합 가능한 인접 쌍이 없을 때 게임 오버 메시지가 표시되는지 확인.
- "새 게임" 버튼 클릭 시 보드/점수/게임오버 상태가 완전히 초기화되는지 확인.
- 방향키 입력 시 브라우저 페이지 스크롤이 발생하지 않는지 확인.
- 모바일 폭(예: 375px)에서 보드와 점수판이 잘리지 않고 정상적으로 보이는지 확인.
- (localStorage 구현 시) 새로고침 후에도 최고 점수가 유지되는지 확인.
- `node build.js` 실행 결과(`docs/` 산출물)가 기존과 동일하게 정상 생성되는지 확인해, 새 게임 폴더가 빌드 파이프라인에 영향을 주지 않았는지 검증.
